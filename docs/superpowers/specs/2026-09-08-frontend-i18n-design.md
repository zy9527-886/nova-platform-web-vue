# Nova Platform Web 前端国际化设计

## 目标

为 `nova-platform-web` 增加简体中文、繁体中文、英语和斯瓦希里语四种界面语言。用户在整体风格设置中切换语言后，固定界面文案立即联动并持久化；刷新页面后继续使用上次选择。

本阶段只处理前端固定文案，不修改后端菜单表，也不翻译用户名、角色名、菜单名称等后端业务数据。

## 语言标识

- `zh-CN`：简体中文
- `zh-TW`：繁體中文
- `en`：English
- `sw`：Kiswahili

## 技术方案

使用 Vue 3 官方生态的 `vue-i18n`。在 `src/locales` 下按语言维护四套结构一致的消息字典，并由统一入口创建 i18n 实例。

`appStore` 保存当前 `locale`，通过现有 `Storage` 工具持久化。切换语言时同步更新：

1. `vue-i18n` 当前语言；
2. Ant Design Vue `ConfigProvider` 的 locale；
3. Day.js locale；
4. 页面根元素的 `lang` 属性。

Ant Design Vue 已提供简体、繁体和英语 locale。斯瓦希里语组件 locale 基于英语 locale 扩展常用分页、日期和空状态文案；Day.js 使用现有 `sw` locale。

## 文案组织

字典按业务域分组，四个语言文件保持相同键结构：

- `common`：查询、重置、新增、编辑、删除、确认、取消、成功、失败等；
- `layout`：整体风格、全屏、个人设置、退出、页签右键菜单等；
- `route`：首页、工作台、系统管理、用户管理、角色管理、菜单管理等；
- `dashboard`：欢迎语、统计卡片和快捷操作；
- `login`：登录页；

- `user`、`role`、`menu`：三个系统管理模块的表格、表单、提示和弹窗文案；
- `settings`、`error`：个人设置与错误页固定文案。

翻译键由 TypeScript 公共结构约束，缺少某语言键时在开发阶段由类型检查暴露。运行时回退语言为 `zh-CN`。

## 路由、菜单、面包屑与页签

静态路由 `meta` 增加 `titleKey`，显示处通过 `t(titleKey)` 动态获取标题。侧边菜单和面包屑直接响应语言切换。

页签不再把翻译后的中文作为唯一标题来源，而是保存路由路径和 `titleKey`；渲染时再翻译。兼容本地存储中已有的旧页签记录：没有 `titleKey` 时回退到原 `title`。

后端 `menuNm` 本阶段保持原值，不参与翻译。

## 整体风格设置

在 `ThemeDrawer` 增加语言选择项，显示：

- 简体中文
- 繁體中文
- English
- Kiswahili

选择后立即生效，不需要点击保存或刷新页面。整体风格设置自身的标题、说明和主题名称也参与翻译。

## 页面迁移范围

迁移当前 `src` 下用户可见的固定中文文案，重点覆盖：

- `BasicLayout`、侧边菜单、面包屑、页签；
- 登录页与首页；
- 用户、角色、菜单管理页面及弹窗；
- 个人设置与 404 页面；
- 请求错误提示等公共消息。

组件中的 Tooltip、表单标签、placeholder、表格列名、按钮提示、确认弹窗和成功/失败消息均改为翻译键。业务接口返回的文本原样展示。

## 验证

- 单元测试验证语言切换、持久化、回退及四套字典键结构一致；
- 类型检查确保组件翻译调用和 locale 映射合法；
- 生产构建验证资源加载；
- 手动检查四种语言切换后，整体设置、布局、首页和三个管理模块的代表性文案立即变化。

## 非目标

- 不增加 `sys_menu_i18n` 或其他后端翻译表；
- 不翻译后端业务数据；
- 不接入自动翻译服务；
- 不根据用户账号在后端保存语言偏好。
